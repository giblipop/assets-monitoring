# HDJV Assistant

The sidebar assistant uses local PHP rules and read-only SQL against the
authenticated user's selected inventory and control databases. It does not
call an AI provider, require an API key, or send questions or inventory records
outside the application server.

It can respond to greetings, explain common system features and database
isolation, identify the system creator, list registered inventory modules and
their fields, summarize table counts, search matching table data, report
missing common asset values, check duplicate asset/serial/reference numbers,
summarize statuses, and show the signed-in user's recent activity. It can
analyze modules registered in the signed-in account's navigation.

System answers include account registration, sign-in guidance, step-by-step
asset editing and table/column/navigation management instructions,
import/export, recycle-bin recovery, shared-code updates, and activity-history
retention. Procedural answers are matched before the generic read-only warning,
so questions such as “how do I edit an asset?” receive instructions instead of
being mistaken for requests for the assistant to edit data.

The assistant can calculate the dashboard's inventory-module count,
record total, issued-this-month count, low-stock modules, and depleted modules
from the signed-in account's inventory database. It follows the dashboard's
current rules: a status containing “stock” is available, low stock is above
zero and at or below 20% of the module's records (with a minimum threshold of
one), and zero available stock is depleted. It can also report the signed-in
account's active/disabled status and aggregate active/disabled account counts.
The account table has no role field, so the assistant cannot determine who is
an administrator and does not list other users' names.

The assistant is private and read-only. It never reads authentication
credentials or other accounts' inventory, and it does not automatically
modify or delete records.

Requests require an active signed-in session and CSRF token, and are limited
to 30 per minute per session. Message text is processed for the request only
and is not saved as chat history. Responses are generated by system rules and
the account's live database, not by an open-ended language model.
